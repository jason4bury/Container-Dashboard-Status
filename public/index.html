Help

Container Dashboard Status shows the Docker containers on each of your machines: whether they're running, how much memory they use, and when they were last updated. It only looks; it never starts, stops or changes anything.

Reading the page

  • Each machine has a card with its running and stopped containers and the memory they use. Click a card's title bar to fold it away.
  • The dot shows the state: green running, amber paused, red unhealthy, restarting or dead, grey stopped.
  • Memory is what the container uses now, as docker stats shows it; the bar is its share of the machine's memory.
  • Image built is when the image was made by its publisher, and when it was pulled where the machine knows that.
  • Last updated is when the container was last made, which is when it was last updated or re-created. Dates over 90 days old are shown in amber.

Finding containers

  • Type in the search box to find containers by name, image or compose project.
  • The All containers list shows only running, stopped or problem containers (unhealthy, restarting, dead, or stopped with an error).
  • Click a column heading to sort by it; click again to reverse.

Refreshing

The page checks again every 30 seconds. Refresh checks at once.

Adding machines

Open Settings and press Add a machine. Pick the kind, fill in its name and address, press Test to check it, then Add. Remove takes one off the page.

The SSH key

  1. In Settings, press Make a key (or Use my own key and paste a private key you already use).
  2. Press Copy beside the line shown, and add it to ~/.ssh/authorized_keys for the SSH user on each other machine. That line lets the key do one thing only: read Docker.
  3. The SSH user must be able to use Docker. On a Synology NAS use an administrator account, and if Docker says permission denied run once on the NAS: sudo synogroup --add docker <user> then sudo chown root:docker /var/run/docker.sock.

When a machine shows an error

The card says what went wrong, such as a machine that can't be reached, an SSH key that isn't accepted yet, or a Docker socket that isn't mounted. Press Test beside it in Settings to try it on its own.
